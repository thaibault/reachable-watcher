reachable-watcher

Check status codes of web servers and sends notification e-mails

Project status

Use case

Watches the reachability of web servers with a single Bash script. Each configured URL is mapped to its expected HTTP status code and to e-mail addresses, which get notified as soon as the URL stops responding as expected and again when it recovers.

Installation

On Arch Linux, build and install the "PKGBUILD" of this repository (it needs the "bashlink" package) and enable the service:

makepkg --install --syncdeps
systemctl enable --now reachable-watcher

Anywhere else, install it globally via npm, which brings its library bashlink along, and link the shipped unit:

npm install --global reachable-watcher
systemctl link \
    "$(npm root --global)/reachable-watcher/reachable-watcher.service"
systemctl enable --now reachable-watcher

The unit starts "reachable-watcher" from "/usr/local/bin" or "/usr/bin". The script alone works as well: it needs "bash" and "curl" and downloads bashlink on its first start if it is missing. E-mails need "msmtp". journalctl -u reachable-watcher shows what the service does.

Configuration

"/etc/reachableWatcher" is a Bash file which overrides the defaults. At least the URLs to check and the sender address have to be set. Each URL maps to its expected status code, followed by the e-mail addresses to notify:

RW_SENDER_E_MAIL_ADDRESS=watcher@example.com
declare -A RW_URLS_TO_CHECK=(
    ['https://example.com']='200 admin@example.com'
    ['https://example.com/missing']='404 admin@example.com dev@example.com'
)
# Optional settings with their defaults:
RW_DELAY_BETWEEN_TWO_CONSECUTIVE_REQUESTS_IN_SECONDS=300
RW_NAME=NODE_NAME
RW_REPLIER_E_MAIL_ADDRESS="$RW_SENDER_E_MAIL_ADDRESS"
RW_VERBOSE=false

"RW_NAME" names this machine in the e-mail subjects, "RW_VERBOSE=true" logs every state change. Run "reachable-watcher" once by hand to check the configuration.

Status codes

Every interval each URL is requested via "HEAD" (certificates are not verified). The response is valid if:

  • its status code equals the expected one or
  • both are one of "200" and "206".

An unreachable URL results in "000", which is only valid if "000" is expected, e.g. to make sure that an internal service stays hidden.

Recipients are only notified when the state of a URL changes, from valid to invalid or back. A URL which is valid on the first check sends nothing.

E-mails

E-mails are sent via "msmtp", so it needs a working "~/.msmtprc" or "/etc/msmtprc", e.g.:

defaults
auth           on
tls            on
tls_starttls   on
tls_trust_file /etc/ssl/certs/ca-certificates.crt
logfile        /tmp/msmtpLog

account        mail
host           smtp.example.com
port           587
from           watcher@example.com
user           watcher@example.com
password       PASSWORD

account        default : mail
